# Multi-guide generator: design

Date: 2026-10-15

## Goal

Turn the Labb 5 generator into a tool that builds any number of breadboard guides. Each guide lives in its own folder with its board layouts, page text and schematics. Adding a guide must not require editing engine code.

## Decisions

- **Authoring stays as it is.** Board layouts are hand-placed JavaScript calls on `makeBoard()`. Page text is Python. Schematics are hand-written SVG in the house style (680-wide `viewBox`, `var(--p)` strokes, `<text>` labels whose first word matches a tag name), optionally generated by a Python script.
- **Output.** One page per guide, `out/<guide>.html`, plus `out/index.html` listing all guides. Everything is published to GitHub Pages. `labb5.html` keeps its URL.
- **Languages.** Node for boards, Python for pages and schematics, as now. No dependencies are added.
- **Out of scope.** A scaffold command for new guides, importing schematics from CAD tools, and porting the Python to Node.

## Success criteria

1. `out/labb5.html` is byte-identical to the build from before the refactor. The one planned exception is the stale header comment in `page.mjs`, which is inlined into the page. It gets edited as the very last step, after the `cmp` check passes.
2. Every board SVG and 3D JSON is byte-identical to its pre-refactor counterpart (at its new path under `out/labb5/`).
3. `out/index.html` lists Labb 5 and links to `labb5.html`. It renders correctly in both themes and down to 320 px.
4. A new guide can be added by creating `guides/<id>/` only.

## Board runner (`engine/boards.mjs`)

Usage: `node engine/boards.mjs <guide>`, run from the repo root.

A guide's `guides/<id>/boards.mjs` has a default export: an object mapping board key to a builder function. A builder takes no arguments and returns a spec:

```js
{ b, names, info, pinned, VH, title, desc }
```

`b` is the board from `makeBoard()`. The other fields are what `finish()` takes today. `info` and `pinned` default to `{}`.

For each key, in insertion order, the runner:

1. calls the builder;
2. places tags exactly as `finish()` does now (`pills.json[key][anchorKey]` > `pinned` > auto-placement);
3. writes `out/<id>/<key>.svg` and `out/<id>/<key>.3d.json`;
4. prints the key and its anchor report.

It reads tag positions from `guides/<id>/pills.json` if that file exists. Board keys must be unique within a guide; they become HTML ids (`bb-<key>`, `model-<key>`) and section ids.

`lib.mjs` exports the four lead colours used by every board (`AMBER`, `TEAL`, `RED`, `BLACK`) so guides don't redefine them.

The guide file imports from the engine with relative paths (`../../engine/lib.mjs`, `../../engine/markings.mjs`). The runner loads it with a dynamic `import()` of its file URL.

## Page runner (`engine/build_page.py`, `engine/page_kit.py`)

Usage: `python -m engine.build_page <guide>`, run from the repo root.

`page_kit.py` holds the content helpers that `build_labb5.py` defines today: `node()`, `c()`, `table()` with `TABLE_HEADS`, `cards()`, `caption()`, `view3d()`, the default `LEGEND`, and a new `section()`. `section()` now takes keyword arguments and returns a dict, so the runner can derive the nav from it:

```python
section(id="led", nav=("p.2", "LED indicator"), eyebrow="Prep task · page 2", title="LED voltage indicator",
        lede="…", schematic="sch_led.svg", rows=[…], cards=[…], sch_cap="…", bb_cap="…")
```

The breadboard key is the section `id`, as it is today.

`guides/<id>/guide.py` defines:

```python
GUIDE = {
    "title": "Labb 5 Breadboard Guide",           # <title>
    "eyebrow": "TNE108 Labbintroduktion · Labb 5 Analoga kopplingar",
    "h1": "Labb 5 circuits, schematic to breadboard",
    "lede": "…",
    "sections": [section(...), ...],
    # optional: "legend": "<section …>…</section>" replaces LEGEND
}
```

The runner:

1. imports `guides.<id>.guide`, with the repo root on `sys.path`;
2. resolves each section's schematic by name: `out/<id>/<name>` (generated) or `guides/<id>/schematics/<name>` (hand-written). If the name exists in both places or in neither, it exits with an error naming the file;
3. renders the sections with the same markup as now;
4. builds the nav from each section's `id` and `nav` in section order, with `--rows: 3 + len(sections)`;
5. writes `out/<id>.html`, with `page-head.html`, the import map, the inlined `viewer3d.mjs` and the inlined `page.mjs`.

The output must match today's `build_labb5.py` byte for byte, so the markup strings move unchanged.

## Schematic helpers (`engine/schlib.py`)

These move unchanged from `sch_ast.py`: `npn`, `res_v`, `cap_h`, `dot`, `t`, `ground`, `probe_box`, `led_down`, `ARROW`, and the constants `P`, `AM`, `TE`.

`fig4()` and `fig5()` move to `guides/labb5/schematics.py`, which imports from `engine.schlib`. Usage: `python -m guides.labb5.schematics`. It writes `sch_ast4.svg` and `sch_ast5.svg` to `out/labb5/`.

## Index page (`engine/build_index.py`)

Usage: `python -m engine.build_index`.

For every `guides/*/guide.py`, sorted by folder name, it renders a card from `eyebrow`, `h1` and `lede` that links to `<id>.html`. The page uses `page-head.html` and its existing `card` / `cols` classes, so it gets both themes and the responsive rules for free. It needs no new CSS beyond what the cards already have. If a link style is missing, it is added to `page-head.html` for both themes. The `<title>` is "Breadboard Guides".

## Build script (`build.sh`)

```
./build.sh            # every guide, then the index
./build.sh labb5      # one guide, then the index
```

For each guide, it runs these steps in order:

1. `node engine/boards.mjs <id>`
2. if `guides/<id>/schematics.py` exists: `$PYTHON -m guides.<id>.schematics`
3. `$PYTHON -m engine.build_page <id>`

After the guides, it always runs `$PYTHON -m engine.build_index`. Guide folder names must be valid Python identifiers (they are imported as modules); the build fails early otherwise.

## Deploy (`.github/workflows/pages.yml`)

Copy `out/*.html` to `_site/`. The site root now serves the index; Labb 5 is at `/labb5.html`.

## Verification

1. Before any change, run `./build.sh` and copy `out/` to the scratchpad as the baseline.
2. After the refactor, `cmp` checks:
   - `out/labb5.html` against `baseline/labb5.html`;
   - each `out/labb5/<key>.{svg,3d.json}` and `out/labb5/sch_ast{4,5}.svg` against its baseline counterpart.
   All must be identical.
3. Serve `out/` with `python -m http.server --directory out`. Check `index.html` and `labb5.html` in the browser: index links, 3D boards load, light and dark themes, 320 px width.
4. Check that a deliberately missing schematic name fails the build with a clear message.
